# CONTEST: An Annotation-Grounded Differential-Contraction Framework for Uncertainty Diagnosis in Large Language Models

Code and derived result files for the manuscript

> **An Annotation-Grounded Differential-Contraction Framework for Uncertainty Diagnosis in Large Language Models**
> Keito Inoshita and Takato Ueno (under review at *Knowledge-Based Systems*).

Every number in the manuscript is a LaTeX macro defined in `numbers.tex`, which is
generated by `kbs/paper/make_numbers.py` from the JSON files shipped in `results/`.
The three data figures are generated by `kbs/paper/make_figures.py` from the same
files, and the overview figure by `kbs/paper/make_overview.py`. Both steps run on a
CPU in seconds and need no GPU, API key or raw corpus.

---

## Repository layout

```
contest_paths.py        path configuration (CONTEST_WORK_DIR, CONTEST_PAPER_OUT)
kbs/
  data_prep/            corpus aggregation and full-corpus sweep inputs
  gpu_sweep/            Qwen2.5 capacity sweep and diversity probes (HF transformers, GPU)
  analysis/             CPU analyses that turn per-item predictions into result JSONs
  paper/                make_numbers.py, make_figures.py, make_overview.py, check_required_macros.py
experiments/            API-based runs still used by the manuscript
                        (frontier E1, delta paraphrases E2, cross-family / MHS E3)
results/                derived result files shipped with the repository (see below)
legacy_aaai/            scripts of the earlier conference version that the KBS manuscript does not use
requirements.txt        CPU dependencies;  requirements-gpu.txt adds torch/transformers/accelerate
.env.example            API-key placeholders for experiments/ (copy to .env)
```

Analysis identifiers used in file names: **C1** ΔAsym bootstrap CIs, **C2** soft-label
scoring and reference-label-noise null, **C3** annotator counts, **C4** stratum
instability and k_i filtering, **C5** endpoint variants, **C6** 14B probe variant,
**C7** capacity sweep / ΔAsym and cost-accuracy (AUBAC), **C8** contraction and
diversity probes, **C9** comparison predictors; **rc3/rc4/rc6/rc9** are the k_i,
mean-independence, beyond-Spearman and monotonicity analyses. Suffixes `_v2`–`_v5`
mark the corrected versions that the manuscript uses.

## Setup

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt          # CPU analyses and paper outputs
pip install -r requirements-gpu.txt      # only for kbs/gpu_sweep
cp .env.example .env                     # only for experiments/ (API keys)
```

Paths are configured in `contest_paths.py`:

| Variable | Default | Meaning |
|---|---|---|
| `CONTEST_WORK_DIR` | repository root | directory that contains `data/` and `results/` |
| `CONTEST_PAPER_OUT` | `<WORK_DIR>/paper_out` | where `numbers.tex` and figures are written |

Run all commands from the repository root.

## Regenerating `numbers.tex` and the figures (no GPU, no raw data)

```bash
python kbs/paper/make_numbers.py      # -> paper_out/numbers.tex
python kbs/paper/make_figures.py      # -> paper_out/figures/fig_capacity.pdf, fig_delta_asym.pdf, fig_auroc_probes.pdf
python kbs/paper/make_overview.py     # -> paper_out/figures/fig_overview.pdf
```

`numbers.tex` contains a `% Generated:` timestamp line; set
`CONTEST_NUMBERS_TIMESTAMP="2026-09-27T16:26:16.748790+00:00"` to reproduce the
manuscript copy byte-for-byte. The regenerated figure PDFs differ from the manuscript
copies only in their embedded `CreationDate`.

`kbs/paper/check_required_macros.py` checks that every result macro family is cited in
the manuscript text; it needs the LaTeX sources (`CONTEST_TEX_DIR=<dir with en/>`).

## First revision (R1, KNOSYS-D-26-23467)

The analyses added in the first revision live in `python/revision_r1/` and
`kbs/gpu_sweep/run_r1_gpu.py`. Every number of the revised manuscript is a macro in
`numbers_r1.tex`, and the two revised result figures are PNG files (600 dpi).

```bash
python python/revision_r1/make_numbers_r1.py   # -> python/revision_r1/numbers_r1.tex
python python/revision_r1/make_figures_r1.py   # -> results/revision_r1_2026-11/figures/*.png
```

Both commands read only shipped files (`results/revision_r1_2026-11/R1_CPU.json`,
`R1_GPU.json`, and earlier result JSONs) and run on a CPU in seconds.

| Step | Script | Output (shipped) |
|---|---|---|
| CPU analyses: alternative strata, stratum-definition CIs, reweighting, full-range slopes, label-noise null, escalation predictors, Holm family | `python/revision_r1/analyze_r1_cpu.py` | `results/revision_r1_2026-11/R1_CPU.json` |
| GPU runs: Qwen2.5 inference seeds (`--mode seed`), OLMo-2 Instruct 1B/7B/13B/32B (`--mode family`), item-language prompts on MultiPICo es/de/fr/it (`--mode native`) | `kbs/gpu_sweep/run_r1_gpu.py` (run next to `run_gpu_sweep_regen_v3.py`) | per-item CSVs (not shipped) |

`analyze_r1_cpu.py` and `analyze_r1_gpu.py` need the per-item prediction files and the

* `revision_gpu_2026-09/regen_analysis/`, `round1_analysis/`, `revision_2026-09/`,
  `llm_e1/e1_summary_*.json` – every file `make_numbers.py` / `make_figures.py` reads.

  the capacity sweep and the diversity / sampling-noise probes (columns `item_id, p_yes,

* `llm_e3/e3_*.csv` – per-item outputs of the 400-item Qwen2.5 sweep and the

notes) were redacted; no numeric field was changed.

## Full pipeline (requires the corpora; the sweep requires a GPU)

```bash
# 1. Aggregate CSC and MultiPICo-en (writes data/raw/* and results/sarcasm/*_aggregated.parquet;
#    --dry-run skips the RoBERTa-based delta_ctx step, which is not used by the KBS manuscript)
python kbs/data_prep/run_pilot_sarcasm.py --dry-run
# 2. Build full-corpus sweep inputs (CSC, EPIC, MultiPICo es/de/fr/it)
python kbs/data_prep/prepare_full_input.py
# 3. GPU sweep: Qwen2.5 0.5B/1.5B/3B/7B/14B/32B (C7), diversity probes and noise control (C8)
bash kbs/gpu_sweep/run_all_v2.sh
bash kbs/gpu_sweep/run_v3_sequential.sh   # OOM-adaptive re-run used for q32b (EPIC, MultiPICo), ll3b (all) and gm2_2b (MultiPICo)
# 4. CPU analyses (in this order)
python kbs/analysis/analyze_c7c8_regen.py
python kbs/analysis/analyze_round1.py
python kbs/analysis/analyze_round1_v2.py        # C2_SOFTLABEL_v2 (and the slower C4/C7/C8/C9 v2)
python kbs/analysis/analyze_round1_v2_fast.py   # C4/C7/C8/C9 v2 files used by the manuscript
python kbs/analysis/fix_multipico_ids.py        # corrects MultiPICo item keys in C4_v2 / C2_v2
python kbs/analysis/compute_c2a_dasym_v3.py
python kbs/analysis/analyze_round2_v3.py
python kbs/analysis/run_c2b_v4.py
python kbs/analysis/run_c2b_v5.py
python kbs/analysis/run_revision_analyses.py    # rc3, rc4, rc6, rc9
python kbs/analysis/fix_rc4.py
python kbs/analysis/run_corrections.py          # rc6 log-prob signal, rc10 overlap
python kbs/analysis/compute_ki_languages.py
# 5. Paper outputs
python kbs/paper/make_numbers.py && python kbs/paper/make_figures.py && python kbs/paper/make_overview.py
```

`analyze_c7c8_regen.py` appends a UTC timestamp to its output names when a file already
exists; `make_numbers.py` reads the timestamped files listed above.

API-based runs (need `.env`): `experiments/run_e1.py` (frontier E1; GPT-4o-mini via OpenAI,
Claude-Haiku-4.5 / GPT-4.1 / Claude-Opus-4.8 via OpenRouter; see the script docstring for
the phase options), `experiments/run_e2_delta_para.py` (paraphrase discrepancy),
`experiments/run_e3_xfamily_api.py` and `experiments/run_e3_mhs_api.py` (cross-family
capacity sweep via OpenRouter).

### Hardware and settings of the capacity sweep

According to the run logs (`results/revision_gpu_2026-09/server_outputs/regen/env_*.json`):

* one NVIDIA RTX PRO 6000 Blackwell Max-Q Workstation Edition GPU (97,247 MiB);
* Hugging Face `transformers` with `device_map="auto"` (no vLLM); BF16 on GPU;
  Python 3.10 on the server;
* models `Qwen/Qwen2.5-{0.5B,1.5B,3B,7B,14B,32B}-Instruct`; diversity probes
  `microsoft/Phi-3-mini-4k-instruct`, `HuggingFaceTB/SmolLM2-1.7B-Instruct`,
  `stabilityai/stablelm-zephyr-3b` (ungated substitutes for Llama-3.2 / Gemma-2);
  sampling-noise control Qwen2.5-0.5B with seed 1234;
* K = 10 samples per item, temperature 1.0, seed 42; batch size 16 in `run_all_v2.sh`,
  and 4 (Qwen2.5-32B), 16 (Phi-3-mini) and 8 (StableLM) in `run_v3_sequential.sh`.

The exact `torch` / `transformers` versions were not recorded in these logs.

  n_annotators, p_ironic, disagreement`).
* `run_costacc_regen.py` (source of `COSTACC_REGEN.json`, whose macros are not cited in
  the manuscript text) was not retained.
